# systemca-nodejs

Node.js LTS builds with no bundled root certificates. Trust comes from the local store.

This repository builds Node 16, 18, 20, and 22 from pinned source with Bazel.
It removes the bundled roots, forces the local store, and tests the result.

## Why

Stock Node compiles its root certificates into the binary.
A distrusted root stays trusted until the next Node release.
The eMudhra emSign roots show this problem. See [docs/EMUDHRA.md](docs/EMUDHRA.md).

## Threat model

- The binary holds no roots. An attacker cannot use a stale root from the binary.
- The host decides trust. A compromised or stale host store gives the same trust to systemca-nodejs.
- OpenSSL does not check revocation here. A revoked certificate from a trusted root still connects.
- The patches change the default trust source only. Code can still pass its own `ca` option.
- `NODE_EXTRA_CA_CERTS` still adds certificates. Anyone who controls the environment controls trust.

## Layout

| Path | Content |
|---|---|
| `MODULE.bazel` | Pinned Node sources, stock controls, and tools |
| `versions.bzl` | The version of each line |
| `patches/<line>/` | Patches, generated by `tools/make_patches.py` |
| `bazel/` | The build rule, its driver, the SDK selector, and toolchain files |
| `node/` | One set of targets per line |
| `tests/` | Source, hermetic, and network tests |
| `trust/` | The pinned test CA bundle |
| `docker/` | The Linux build image |
| `docs/` | Notes about hermeticity and the eMudhra hosts |

> The project was called rootbeer before. Target names (`//node:rootbeer_22`), the `ROOTBEER_*` environment variables, the `rootbeer-linux` image, and the `node-v*-rootbeer-*` artifact names keep the old prefix for now. A later change renames them.

## Build and test on macOS

```sh
bazel build //node:rootbeer_22 //node:dist_22 --output_groups=+dist
bazel test //tests:source_22_test //tests:hermetic_22_test //tests:network_22_test
bazel run //:dist_22
```

Change `22` to select a different line. `bazel run //:dist` collects every line in `./dist/`.
Put local flags in `user.bazelrc`. Git ignores this file.

## Build and test on Linux

A Linux host can use the same commands if it has Bazel, the POSIX tools, and these libraries:
`libstdc++`, `libz`, `libzstd`, and `libxml2`.

A container supplies these inputs on any host:

```sh
docker build --platform linux/amd64 -t rootbeer-linux docker
docker run --rm --platform linux/amd64 \
  -v "$PWD":/src:ro -v rootbeer-bazel-cache:/cache rootbeer-linux \
  bazel --output_user_root=/cache build --lockfile_mode=off --symlink_prefix=/ --jobs=1 \
  //node:rootbeer_22 //node:dist_22 --output_groups=+dist
```

The container mounts the source as read-only. Bazel does not write the lockfile or symlinks for this reason.
The build uses 5 compile jobs on Linux, because the default Docker VM has 8 GB of memory.
On Apple Silicon, Docker emulates x86_64, so the build is slow.

## How the patches work

`tools/make_patches.py` generates each patch from a verified source tree.
Each replacement must match exactly once. A new Node release that moves the trust code stops the tool.

| Patch | Lines | Effect |
|---|---|---|
| `0001-empty-root-certs` | All | Empties `src/node_root_certs.h` |
| `0002-force-local-store` | All | Calls `X509_STORE_set_default_paths` for every default store |
| `0003-libcxx-19-char-traits` | 16, 18 | Adds the `char_traits<uint16_t>` that libc++ 19 removed |
| `0004-zlib-macos-test` | 16, 18 | Stops old zlib from treating macOS as classic Mac OS |

`0002` differs between the lines:

- **Node 16, 18, and 20:** The patch removes the root array and the code that loads it from `NewRootCertStore`.
- **Node 22:** The patch empties `GetBundledRootCertificates` and keeps `--use-system-ca`.
- **All lines:** `tls.rootCertificates` is an empty array.
  `--use-bundled-ca` has no effect, and it can appear with `--use-openssl-ca`.
- **All lines:** `OPENSSLDIR` is `/etc/ssl`, not the macOS path `/System/Library/OpenSSL/`.

`SSL_CERT_FILE` and `SSL_CERT_DIR` select the store. With no value, OpenSSL reads `/etc/ssl/cert.pem` and `/etc/ssl/certs`.

## Tests

- **`source_N_test`** reads the patched source. It is cacheable, and it needs no Node build.
- **`hermetic_N_test`** runs the binary and uses a loopback TLS server. It is cacheable.
  It checks the version, the empty root list, the flags, the binary contents, and the linked libraries.
- **`network_N_test`** connects to public hosts. It has the tags `requires-network`, `no-remote`, `no-cache`, and `external`.
  It checks valid hosts and eMudhra hosts, with stock Node as a control.

A DNS or network failure gives a test error. It never gives a pass.
[docs/EMUDHRA.md](docs/EMUDHRA.md) tells how the tests read each result.

## Known gaps

- The build is not fully hermetic. See [docs/HERMETICITY.md](docs/HERMETICITY.md).
- macOS builds read the Apple SDK from the host, because its license does not allow a pinned copy.
- Bazel sandboxes do not hide host read paths, so the tests give narrow evidence of isolation.
- No test compares two builds, so byte-for-byte reproducibility is not proven.
- The macOS artifacts need macOS 14 or later.
- systemca-nodejs connects to the emSign G1 hosts when the local store holds emSign G1.
  On 2026-10-30, the curl Mozilla bundle and macOS `/etc/ssl/cert.pem` both held emSign roots.
- The eMudhra hosts may stop. The network tests then report an error, and the host list needs a change.
- CI runs the source tests only. The local builds are the source of truth.
